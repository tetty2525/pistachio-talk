# /deepen <phrase-id> — Stage 2 深掘り

`phrases/` の既存エントリを1件選び、語源・文化史・比喩の論理を掘り下げる。

## 手順

1. **対象を読む**
   - `phrases/<lang>/<slug>.md` を id から特定して読む
   - 既存の `verification.status` を確認する（Stage 2 化には `stage: 1` 以上、つまり `cross_checked` 以上が前提。`single_source` のままなら先に `/verify-phrase` を勧める）

2. **語源調査**
   - Web検索・辞書サイトで語源の裏取りを行う。既存出典（多くは T2）の主張をそのまま鵜呑みにせず、可能なら T1（辞書・学術）での確認を試みる
   - 新しい主張を書いたら、その主張に対応する出典を `sources[]` に追加する（`covers` は適切に設定。語源の裏取りは3点テストの `meaning`/`usage` を必ずしも要求しないが、追加した出典の性質は正直に記録する）

3. **文化・歴史背景の調査**
   - このフレーズがいつ・どのように広まったか（歌謡・映画・世代・地域差など）を調べる
   - 見つからない場合は無理に埋めず、「未解明」であることを正直に書く（Stage 2 完了条件は「実質的な内容」であって「決定的な答え」ではない）

4. **比喩の論理の精緻化**
   - なぜその比喩が褒め言葉として成立するのかを、文化的な文脈込みで説明する

5. **本文執筆**
   - `## 語源` `## 文化・歴史背景` `## 比喩の論理` の各見出しに実質的な内容を書く（空見出しのままだと Stage 2 の CI 検証が通らない）
   - `usage_examples[]` を追加で見つけていれば拡充する
   - `register_warnings_ja` を必要なら精緻化する

6. **更新**
   - `stage: 2`、`updated: <今日の日付>` に更新
   - `researched_by` に自分（実行AI）のidを追加（重複しないように）

7. **検証・コミット**
   - `npm run validate` を通す
   - ブランチを切ってPR、または軽量運用中ならセルフレビューでコミット
