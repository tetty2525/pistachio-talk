# /add-phrase — 単発追加

ユーザーが既に知っているフレーズ、あるいはこれから一緒に調べたいフレーズを1件、対話しながら追加する。

## 手順

1. **聞き取り**
   - フレーズ原文・言語・（分かれば）出典URLをユーザーに尋ねる
   - 出典URLが未定なら、ここでWeb検索を行い候補URLを一緒に探す

2. **キザ判定（第6条）と3点テストの検証（必須・省略不可）**
   - まず第6条判定: フレーズがキザ4要素（metaphor/wit/poetic_image/cultural_allusion）のどれに当たるか確認する。直接的な機能フレーズの場合は、収録対象外であることを理由と共にユーザーに伝えて終了する
   - 提示・発見されたURLを**実際にfetch**する
   - 原語表記・意味の説明・使用例（または使用場面）の3点を確認する
   - 満たさない場合、追加のURLで補完を試みる。それでも揃わなければ**エントリを作らずに**不足している点をユーザーに報告して終了する（`leads/` に `status: open` として残す提案をしてもよい）

3. **エントリ作成**
   - `templates/phrase.md` を雛形に `phrases/<lang>/<slug>.md` を作成
   - IPA発音記号・ローマ字転写・`gloss_ja` を埋める（不明な項目はユーザーに確認するか、Web調査で補う）
   - `origin_type` を判定する（第2条: フィクション由来なら現実の流通を示す別出典が必要。無ければこの場でエントリ化しない）
   - `verification.status: single_source`、`stage: 0`
   - `found_by`: ユーザーのcontributor id、`researched_by`: 実行AIのid

4. **検証**
   - `npm run validate` を通す

5. **コミット**
   - ブランチ `phrase/<id>` を切ってコミット。PRを作るかセルフマージするかはユーザーに確認する

## 注意

出典を実際にfetchせずにsourcesへ書くことは憲法第1条違反。「もっともらしいURL」を推測で書いてはならない。
